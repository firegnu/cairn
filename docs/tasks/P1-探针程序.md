### `cairn-probe hook <claude|codex> [--dir <探针目录>]`
- 探针目录：先看 `--dir`，再看环境变量 `CAIRN_PROBE_DIR`。两者都没有：不记日志，按"没有 plan"处理输出。
- 读 stdin 全部内容，解析成 JSON，追加一行到 `<探针目录>/events.jsonl`。每行的内容：
  - `received_at`：收到的时间（RFC 3339，精确到毫秒）
  - `agent`：命令行里的 `claude` 或 `codex`
  - `pid`：探针进程号
  - `env`：`{"CAIRN_DISABLE": <值，没有则 null>}`（实测 H 项用：看 hook 进程能不能继承 agent 的环境变量）
  - `input`：stdin 的 JSON，**脱敏后**再写（见下）
  - stdin 不是合法 JSON 时：不写原文，只写 `{"parse_error": "<错误说明>", "bytes": <长度>}`
- **脱敏**（硬性要求，项目隐私规矩）：
  - 顶层的 `prompt`、`last_assistant_message` 字段，值换成 `{"redacted": true, "chars": <原文字符数>}`，原文不落盘；
  - `transcript_path` 只把路径字符串原样记下，**绝不打开或读取这个文件**；
  - 其他字段原样记。
- 读 `<探针目录>/plan.json` 决定输出。格式：

  ```json
  {
    "session_start": { "text": "要注入的文字" },
    "stop": { "mode": "allow", "reason": "续跑原因文字" }
  }
  ```

  - 两个键都可以省略；`plan.json` 不存在等同于两个都省略。
  - `stop.mode` 只有两种：`allow`（一直放行）、`block_first`（同一个 `session_id` 第一次 Stop 时续跑，之后这个会话的 Stop 都放行）。"已经 block 过"的状态按会话记在探针目录里。
- 按事件名（输入里的 `hook_event_name`）输出：
  - `SessionStart`：有 `session_start.text` 时，输出 `{"hookSpecificOutput":{"hookEventName":"SessionStart","additionalContext":"<text>"}}`；没有时不输出。两种工具相同。
  - `Stop` 要续跑：输出 `{"decision":"block","reason":"<reason>"}`。两种工具相同。
  - `Stop` 放行：claude 不输出；codex 输出 `{}`（Codex 的 Stop 不接受空输出以外的纯文本，这里统一给 `{}`）。
  - 其他事件：不输出。
- 退出码**一律 0**：读不到 stdin、JSON 坏了、目录写不进、plan.json 坏了，都只是尽量记录然后放行。不使用退出码 2（对 Stop 来说 2 表示续跑）。

### `cairn-probe save [--source <ID>] [--nothing-new]`
- 写入位置：`${XDG_STATE_HOME:-$HOME/.local/state}/cairn-probe/saves.jsonl`，目录不存在就创建。这个位置故意放在工作区外面，用来测 Codex 沙箱能不能写进去。
- 每行：`saved_at`、`source`（没给就是 null）、`nothing_new`（布尔）、`cwd`、`body`（stdin 全文；`--nothing-new` 时不读 stdin，记为 null）。
- 成功：stdout 只输出一行 `saved`，退出码 0。
- 写入失败：stderr 输出一行原因，**退出码非 0**。实测要靠这个看出沙箱有没有拦。
