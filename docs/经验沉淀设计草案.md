## 2. 什么算经验（已定，E2；例子和边界是草案）

记“下次做同类事时用得上的怎么做、别怎么做”。最可信的来源有三种：

| 来源 | 例子（都是 2026-10-16 本仓库里真实遇到的） |
|---|---|
| 试了失败，换个法子成了 | macOS 没有 `timeout` 命令，脚本里给命令设超时要换办法 |
| 工具的行为和预想的不一样 | `cairn install --agent claude --dry-run` 显示“将修改”，其实只是放行规则换了顺序，内容不变，不必重装 |
| 用户纠正了 agent 的做法 | 背景记录里把主控的话写成了“用户认为可以”，用户的话要照原样记，不能把主控的判断算到用户头上 |

和账的三类怎么分：

- 现在是什么样 → 现状（state）
- 等着定的、要观察的 → 悬而未决（open）
- 用户交代、一直沿用的规矩 → 约定（convention）
- 干活里学到的做法和教训 → 经验（lesson）

用户把一条经验说成“以后都这样做”，它就成了约定，记成 convention，不重复记 lesson。

不记：拿不准的；只发生一次、以后不会再遇到的；这个会话里的权宜之计；会话自己做到哪了（那归会话摘要）。

## 4. 谁来写：旁路模型（已定，E3、E7；细节是草案）

### 4.1 什么时候写

和记账同一次调用（DESIGN §8.9），时机不变：会话安静 3 分钟、会话结束、同一条工作线上有新会话开局，或者用户运行 `cairn summarize`。不多调一次 Codex。

### 4.2 交给模型什么

和记账一样：要求文字、当前所有有效条目（含经验）、这个会话新增的会话记录。要求文字里加一段讲经验（§4.6）。

### 4.3 模型输出什么

格式不变，类多一种：

```text
ADD <state|open|convention|lesson> | <标题> | <正文> | <依据>
EDIT #<no> | <新标题> | <新正文> | <依据>
CLOSE #<no> | <理由> | <依据>
```

### 4.4 检查和写入

- 检查照 §8.9，只是 `ADD` 的类多认一个 `lesson`。
- 每批上限各算各的（已定，E12）：账的变动（`ADD` 前三类，和对它们的 `EDIT`、`CLOSE`）最多 10 笔，经验的变动（`ADD lesson`，和对经验条目的 `EDIT`、`CLOSE`）另外最多 5 笔。任何一边超了，整批不合格，照旧整批丢掉。这样账的行为和现在一样；经验每次最多 5 条，也挡住“什么都当经验记”。

### 4.5 不设确认（已定，E4）

直接生效。兜底和账一样：每笔带依据；了结的不删，`cairn ledger reopen` 能恢复；`cairn ledger log` 看得到最近的变动。写错的经验比写错的现状更容易带偏 agent（agent 会照着做），所以要求里收紧入口（§4.6）。

### 4.6 要求里加的一段（草案）

接在 DESIGN §9.6 “账里只有三类条目”之后：

```text
- lesson（经验）：做过才知道的做法和教训，下次做同类事时用得上，比如试了失败、换个法子成了；工具的行为和预想的不一样；用户纠正了做法。写清在什么情况下、该怎么做或别怎么做。

经验的要求：
- 拿不准的、只发生一次以后不会再遇到的、只是这个会话里的权宜之计，不记。
- 用户说“以后都这样做”的，记成 convention，不记成 lesson。
- 账里已有相同或相近的经验，改那一条，不要重复新增；两条说的是一回事，改其中一条、了结另一条。
- 经验被证明不对、或者条件已经不成立，了结它，理由写清。
```

措辞试点后再调。

## 5. 开局注入（已定，E5、E6、E11）

- 在“项目的账”之后单独一节“经验”，只给有效的经验，每条 `#no`、标题、正文、多久前、来源。
- 预算：总量不变，约 9,000 字符。账最多约 3,000，经验最多约 1,500，会话摘要等其余部分约 4,500。账或经验用不满，余下的给会话摘要。
  - 为什么不加总量：Claude 的文档上限是 10,000 字符（DESIGN §9.1），再加就顶到边上，越界行为没测过。
  - 代价：会话摘要那份从约 6,000 变成约 4,500。实际常常用不满，但长会话的摘要会被截得更早。
- 经验超出它那一份时：最久没改的只给标题；再不够，只给“N 条经验，查看 `cairn ledger`”。
- 补注入（DESIGN §9.5）：经验的变动和账的变动一起，放在“项目的账有变动”那一段里，每笔标上类。

## 6. 命令（已定，E9：不加专门命令；细节是草案）

全用 `cairn ledger`：

- `cairn ledger` 多一组“经验”；`cairn ledger add lesson <标题>`；`edit`、`close`、`reopen`、`delete`、`log` 不变。
- `cairn ledger --json`：`kind` 多一种取值 `lesson`。
- `cairn ledger export`：多一组“经验”。

## 7. 给 paddock 的输出（已定，E9；细节是草案）

## 10. 风险（草案）

| 风险 | 怎么减轻 |
|---|---|
| 写错的经验持续带偏后面的会话 | 收紧入口（§4.6）；每条有依据；`log` 看得到；能了结、能恢复 |
| 记得太碎，什么都当经验 | 要求里写明不记的几类；试点看实际数量再调措辞 |
| 和约定重复 | 要求里写明“用户说以后都这样”的记成约定 |
| 会话摘要的份额变小，长会话摘要截得更早 | 账和经验用不满时余下的给摘要；试点看 |
| 经验越积越多，注入只剩标题 | 模型合并、了结；以后再考虑按需查 |
| 经验正文里带进路径以外的敏感内容 | 照账的要求：不抄密钥、口令、令牌；误存的用 `cairn ledger delete` |
| 要求变长，记账那次调用更慢、更容易输出不合格 | 输出格式不变；不合格整批丢掉照旧；试点看失败率 |

## 12. 开发阶段的验收（已定，E14）

主控按用户使用的角度起草，用户：“验收可以”。装上之后用户在真实项目里照这六条验；开发时 agent 只能用假的 `codex` 测，“记得准不准”要用户真用了才知道。

1. **会自己记**：在已采用的项目里正常干几次活，做过才知道的教训会出现在“经验”里，每条看得到是哪个会话记的、依据什么。
2. **不乱记**：一次性的事、权宜之计不会被记成经验；用户交代的规矩记成约定，不记成经验。
3. **会合并、会了结**：重复的经验会被合并；被证明不对的会被了结，看得到理由。
4. **开局看得到**：Claude 和 Codex 的新会话开局，都能看到“经验”一节，和项目的账、会话摘要分开，三样都在。
5. **能看、能改、能导出**：`cairn ledger` 里有“经验”一组；记错的能改回来、能恢复；导出里有经验。
6. **原来的不坏**：项目的账和会话摘要照常工作；paddock 不改也不出错。
