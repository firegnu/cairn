# 任务：Codex 把会话记录压缩成 .zst 后，cairn 照样能读

2026-11-11，用户让主控记成草稿任务。**草稿，没派。** 等 P1-27（接入 canter）合并后再派：两件都改 `transcript.rs`、`sidecar.rs`。

## 起因和用户原话

开局注入一直挂着“另有 3 个会话记账没写成”。主控 11-11 查了：三个都是 10-15、10-16 的 Codex 实测会话（测跨工具接续，没有要补记的内容），10-24 记账时报“会话记录读不了或解析不了：transcript I/O failure: NotFound”。按文件名找（没打开内容），三个文件都还在，只是被 Codex 压缩改名了：`rollout-….jsonl` 变成同目录的 `rollout-….jsonl.zst`。cairn 记的还是原路径，所以找不到；连着失败两次后不再自动试，但 cairn 没有办法把它们标成“不用管”，每次开局都报。

正常会话几分钟内就写完摘要和账，碰不到压缩（这三个是 8 天内被压的）；只有当时没写成、之后又要补的会话会撞上。

主控给了两个办法：A 找不到原文件、旁边有 `.zst` 时解压了读；B 当作已归档，不再重试、不再报。用户：「选 A，写成草稿任务」。

## 要做的

`sessions.transcript_path` 指的文件不在、同目录有同名加 `.zst` 的文件时，cairn 解压了照样读，写摘要和记账都照常；开局那一行“记账没写成”随之消失（这三个会话补记成功，或者判成没什么可写）。

## 怎么算做完

用户没另说验收，以上面“要做的”为准。

## 主控的理解（待用户确认）

- 只看 hook 给的那个路径加 `.zst` 这一个文件，不去列、不去翻 Codex 的目录（D12、§12 的范围不变）；打开前照旧核对是普通文件、属主是当前用户。
- 读到的位置（`summarized_bytes`、`ledger_bytes`）按解压后的字节算，和压缩前的原文件一致，增量读照旧。挑“该写摘要、该记账的会话”时比的文件大小，也要按解压后的算，不能拿压缩后的大小当成“文件被重写变短”。
- 解压用成熟、活跃维护的 zstd 库；解压后的内容只在内存里，不另存文件（§12）。
- 只管 Codex；Claude、canter 没见过压缩，照旧。
- 动工前改 `docs/DESIGN.md` §8.8“读会话记录”和 §10.2 Codex 那条“会话记录”。
