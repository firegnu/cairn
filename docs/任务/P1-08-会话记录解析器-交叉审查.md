### R1（必须改）：无换行末行被消费后，后来补上的换行会阻断续读

- **位置**：`crates/cairn/src/transcript.rs:95-109`；现有续读测试 `crates/cairn/tests/transcript.rs:68-89` 停在读取无换行末行，没有再追加下一条。
- **问题**：第一次读取完整 JSON、但末尾还没有换行时，`end_offset` 已推进到 JSON 之后。写入方再追加 `
` 和下一条完整消息，第二次从该偏移读到的首行只有换行。它解析失败，后面又有数据，于是返回 `InvalidJson { line: 1 }`，后续正常对话无法继续读取。偏移正好落在分隔换行之前，而不是下一条记录开头。
- **合成复现**：临时普通文件先只写用户消息“问题”的完整 JSON，不加换行；调用 `extract(..., 0)` 成功；再追加换行和助手消息“回答”，从上次偏移续读。Claude 首次偏移为 46、Codex 为 117，两者第二次均实得 `Err(InvalidJson { line: 1 })`。输入完全合成，直接调用本次编译的解析器，没有改实现或仓库测试。
- **改法**：保留完整无换行 JSON 可读的约定时，续读应识别并消费上一条已消费记录后来补齐的分隔换行，只处理该边界，不普遍放过损坏的中间行。补两家的“无换行读取成功 → 补换行并追加消息 → 从返回偏移再读”回归，确认只返回新消息且偏移继续推进。
