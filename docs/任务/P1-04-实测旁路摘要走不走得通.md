## 测试会话

- 交互式的被测会话一律用 corral 开：`corral start cairn/test-<名字> --unique --cwd <p1-lab 下的仓库> --label role=test --env CAIRN_DISABLE=1 -- <claude 或 codex 及参数>`。`CAIRN_DISABLE=1` 是为了让用户机器上真实安装的 cairn hook 不掺进来；你自己放在实验仓库里的 hook 不受它影响。
- 非交互的（`claude -p`、`codex exec`）是一次性命令，可以直接跑，同样带 `CAIRN_DISABLE=1`（C2 里要求不带的那一次除外）。
- 被测会话用工具的默认权限和默认沙箱，不加 `--yolo`、`--dangerously-skip-permissions` 这类参数。Codex 的项目级 hook 没有持久信任时，可以对你自己的测试调用加 `--dangerously-bypass-hook-trust`（只对那一次调用生效），报告里写明。
- 模型：被测会话 Claude 用 `--model sonnet --effort medium`，Codex 用 `-m gpt-5.6-luna -c 'model_reasoning_effort="medium"'`。Claude 的额度紧：Claude 这边的回合数压到够回答问题的最少。
- 对自己开的 `cairn/test-*`，可以用 `corral send / keys / wait / status / reply / stop`。每个用完立刻 `corral stop`。任务结束时 `corral ls` 里不能再有你开的。
- `corral ls` 里其他的 agent 都不是你的：不要对它们执行 `stop`、`send`、`keys`，也不要 attach。

## 要做的

在 Claude Code 和 Codex 上各测一遍（C 组除外，按各条写的来），回答下面每个问题，写成报告 `docs/调研/旁路摘要可行性实测.md`。

**A. 会话记录拿不拿得到、全不全**

- A1. Stop、SessionEnd 两种 hook 的输入里有没有 `transcript_path`，那个文件在不在。
- A2. Stop 触发的那一刻、SessionEnd 触发的那一刻，文件里有没有刚结束那个回合的用户提示和最终回答（在提示和回答里放合成的口令来核对）。没有的话，隔多久才有。
- A3. 三种结束方式之后，文件里最后一个完整回合在不在：`/exit`；`corral stop`；强杀（只对你自己开的测试会话，用 `corral status` 给出的 `agent_pid`，`kill -9` 这一个 PID）。三种各自有没有 SessionEnd。
- A4. 文件的格式：是不是一行一条；用户消息、助手回答、工具调用各靠哪些字段分辨；用 `jq` 能不能把“用户说了什么、助手答了什么、调了哪些工具”抽成一段纯文本。只记字段名和结构。

**B. hook 里能不能拉起后台进程**

- B1. 在 Stop hook 和 SessionEnd hook 里各拉起一个脱离 hook 的后台进程，hook 自己在时限内返回（SessionEnd 的时限见 hooks 资料）。后台进程在 hook 返回之后、在会话退出之后还活不活着（比如让它睡 60 秒再写一个标记文件）。A3 的三种结束方式都看一下。
- B2. 这个后台进程读不读得到会话记录文件，能不能联网。Codex 的默认沙箱下也要测。

**C. 旁路调用**

- C1. 在 B 的后台进程里跑 `codex exec`（`-m gpt-5.6-luna -c 'model_reasoning_effort="medium"'`），把 A4 抽出的文本交给它，让它按 `docs/DESIGN.md` §6.3 的六节格式写一份摘要，结果写进实验目录。能不能成、多久、CLI 报告的用量是多少。被测会话是 Claude 的和是 Codex 的各做一次。
- C2. 自己触发自己：旁路这次 `codex exec` 带 `CAIRN_DISABLE=1` 时，实验仓库里的 hook 会不会被它触发；不带时会不会。它在哪个目录下运行会不会影响结果。
- C3. 多出来的会话：看 `--help` 和官方文档，有没有让这次调用不留会话的参数；有就用上，确认摘要照常写得出来。确认不了会不会留下，就写未知，不要去翻 `~/.codex`、`~/.claude` 下的目录。
- C4. 换成 `claude -p`（用最便宜的模型）当旁路，把 C1 做一次，同样看 C2、C3。只做一次。
