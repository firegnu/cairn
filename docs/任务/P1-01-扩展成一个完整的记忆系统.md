## 主控的理解（待用户确认）

以下是主控对用户原话的理解，用户还没确认，不是需求。

- **agent 的记忆**：不随某件活结束而过期的东西，比如用户的偏好、项目的约定、踩过的坑。现在的 cairn 只记一种东西：这条工作线上次停在哪。
- **RSI**：主控理解成 agent 的自我改进，即 agent 从被纠正、做错、做对的经历里沉淀经验，这些经验反过来改变它以后的做法，形成闭环。
- **跨 agent 的记忆共享**：一个 agent 记下的东西，别的 agent 也能用上。

## 和现有设计的关系

- 这个方向不算推翻原设计。`docs/DESIGN.md` 的 D2 把长期记忆、检索、自动遗忘、全局记忆列为“以后再议”，是推迟，不是否决。
- 要动的已定决定和范围（动工前先改 `docs/DESIGN.md`）：
  - D2：首版只做“工作接续”这一项。
  - §13“不做”里的几条：长期条目、检索、自动遗忘、全局记忆；跨机器同步和 MCP 要不要动，看下面的回答。
  - D7：记录是带来源的历史，不是当前指令。自我改进的经验存在的目的就是改变以后的行为，和这一条有张力。
  - 派出去的 agent 现在一律带 `CAIRN_DISABLE=1`（ranch R2）。共享如果包含它们，这条要重开。
- 和现在的接续记录差在哪：
  - **选择**：接续记录是短命的，新的顶旧的，开局全量注入就行。长期记忆越积越多，要决定每次注入哪些，以及哪些已经过时或当初就写错了。
  - **约束力**：一条写错的经验会持续带偏之后的每个会话，现在“可以更正、撤回、恢复”的手段够不够要重新看。
- Claude Code 自带的记忆只有 Claude 能用，Codex 读不到。cairn 做这件事的独特之处在跨工具，主控建议把这一点当作新方向的主轴。
