## 要做的

上网查，写一份中文报告 `docs/调研/agent记忆系统现状.md`，回答用户的两个问题：这个方向现在进展到哪了；专门做这件事的项目都是怎么做的。

用户点名了三块，报告按这三块组织：

- **agent 的记忆**：跨会话留下来、以后还用得上的东西（不只是“上次停在哪”）。
- **RSI**：主控理解成 agent 的自我改进，即从经历里沉淀经验、反过来改变以后的做法。用户还没确认这个理解；这个词在这个领域里通常指什么、有没有别的常见含义，报告里说清楚。
- **跨 agent 的记忆共享**：一个 agent 记下的，别的 agent 也能用上。包括不同厂商的工具之间（比如 Claude Code 和 Codex）、同一套多 agent 系统内部。

查的对象：

- 各家 coding agent 自带的记忆现在做成什么样（至少 Claude Code、Codex，其余你认为有代表性的）。
- 专门的记忆项目和产品，开源的优先，侧重能给终端里的 coding agent 用的。
- 有影响的论文和厂商的工程文章。

每个有代表性的项目，尽量说清楚这几件事（查不到就写查不到，不要猜）：

- 存什么（记忆分哪几种），存在哪（文件、数据库、向量库、图）；
- 什么时候写、谁来写（agent 主动、hook、事后另一个模型提炼）；
- 什么时候读、怎么选（全量注入、检索、agent 自己查）；
- 怎么更新、合并、淘汰过时的；
- 怎么对付写错的记忆、被污染的记忆；
- 怎么接进 agent（hooks、MCP、指令文件、SDK），是否跨工具；
- 成熟度：谁在维护、最近是否活跃、有没有实际使用的迹象。

最后单列一节：这个方向上公认还没解决好的问题，以及各家做法之间真正的分歧在哪。
