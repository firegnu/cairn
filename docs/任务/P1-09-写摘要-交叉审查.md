### R1 — 必须改：生成期间的新保存会被未读过它的摘要顶替

- **位置**：`crates/cairn/src/sidecar.rs:326–346`（取上一版并构造输入）、`349–365`（提交时重新选上一版并顶替）。
- **问题**：`Lease` 只挡住另一个摘要写者，挡不住合法的同来源 `cairn save` 及其收取。模型开始后，若同来源、同工作线有一条新的手动保存入库，提交事务里的第二次 `previous_checkpoint` 会选中它，并让旧输入生成的摘要顶替它。这条手动记录根本没进入模型输入，却退出了默认列表和下一次接续上下文。旧正文仍能通过 `list --all` / `show <ID>` 找回，因此不是物理删除；缺陷是并发更新被静默遮掉，违背 §8.8 / R8 中手动保存应成为后续摘要输入的用途。
- **复现证据**：隔离 HOME / XDG、临时 Git 仓库、合成会话；假 `codex` 读完输入后停在屏障。此时执行 `save --source claude:one`，正文含 `manual-during-generation`，再用 `show` 收取；最后放行假模型。假模型已确认输入不含该标记，输出固定为 `summary-from-old-input`。结果默认列表仅 1 条 sidecar；手动记录的 `replaced_by` 指向该 sidecar。临时测试 `review_concurrent_save_must_not_be_replaced_by_summary_that_never_read_it` 在“手动记录仍应可见”的断言处失败，子进程已正常回收，不是夹具或编译错误。
