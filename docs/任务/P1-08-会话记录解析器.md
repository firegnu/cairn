## 要做的

照 DESIGN §8.8“读会话记录”实现一个函数，后面的任务会这样调用它（名字和字段照写）：

```rust
pub struct Excerpt {
    pub text: String,     // 抽出来的文本，已截短、已按总长上限处理
    pub end_offset: u64,  // 读到哪了：最后一条完整的行之后的字节偏移，下次从这里续读
    pub restarted: bool,  // 文件比 from 还短（被重写过），这次按全文读的
}

pub fn extract(agent: crate::turn::Agent, path: &Path, from: u64) -> Result<Excerpt, Error>;
```

- 从字节偏移 `from` 开始读（0 就是全文）。文件比 `from` 短，按全文读，`restarted` 为真。
- 每家一个薄的解析器，抽出几种行：用户说的话、助手说的话、调了哪个工具和参数、工具的结果。Codex 要把 `event_msg` 里的 `item_completed` 也算进去（P1-05）。文本里每种行怎么标，你定，写在模块文档里。
- 大段的参数和结果截短到 500 字符；抽出来的文本总长上限 60 KiB，超出时保留开头四分之一和结尾四分之三，中间写明省略了多少。两个数做成常量。
- 不认识的行跳过。最后一行不是完整的 JSON 就丢掉，`end_offset` 停在它前面。其余某一行解析不了，或者这次读的部分抽不出任何用户或助手的话，返回错误。
- 打开文件后，用打开的那个文件句柄核对它是普通文件、属主是当前用户，不是就返回错误。
- 错误里只写原因（类别、行号这类），不带会话内容。`Error` 的变体你定。
- 只读文件，不写任何东西，不另存文件。
