# 旁路摘要可行性实测

2026-10-12。Claude Code **2.1.296**；Codex **0.162.1**。本报告只回答 P1-04 的本机合成实测问题，不修改 cairn 的设计，也不把有限样本当成通用保证。

**本轮结果：两家的正常退出路径都走通了“从 hook 给出的路径读记录 → 脱离 hook 的后台进程 → 已登录 CLI → 六节摘要”。** 但 Claude 的 Stop 即时记录缺最终回答；两家强杀均未观察到 SessionEnd，Codex 的一次 `corral stop` 也未观察到；旁路设置 `CAIRN_DISABLE=1` 或不留会话参数，都没有阻止实验 hook 再次触发。下文逐项给出范围和证据。

## 1. 方法、边界与证据索引

- 被测交互会话全部通过 Corral 创建，名称以 `cairn/test-sc-` 开头，带 `role=test`、`CAIRN_DISABLE=1`、实验用 `XDG_STATE_HOME`。Claude 用 `--model sonnet --effort medium`，记录中的实际模型为 `claude-sonnet-5-5`；Codex 用 `-m gpt-5.6-luna -c 'model_reasoning_effort="medium"'`。
- 未传权限/沙箱扩大参数。Claude 三个交互样本的 Stop 报 `permission_mode="auto"`，Claude print 旁路报 `default`；这是本机默认启动结果，不能称为干净安装的默认值。Codex 被测记录的 `turn_context.payload` 报 `sandbox_policy.type="workspace-write"`、`network_access=false`、`approval_policy="on-request"`。
- 保留真实 HOME 让 CLI 使用已有登录态；实验状态写到仓库外 `p1-lab/sidecar/state/`。C2 唯一一次去掉 `CAIRN_DISABLE` 时仍使用独立 `XDG_STATE_HOME`。没有改真实配置、打开真实 cairn 数据库、读取工具记忆文件或 Corral 事件文件。
- 两份实验项目 hook 配置改前分别复制为原文件旁的 `*.before-sidecar-20261012`，随后替换为本轮探针。配置仅有 SessionStart、UserPromptSubmit、Stop、SessionEnd；不注入提示、不续跑、不保存输入中的 `prompt` 或 `last_assistant_message`。探针保存输入字段名，以及会话关联、事件名、路径、时间、环境开关等必要字段。
- hook 入口是实验目录的 `bin/hook.sh`，调用现有 Node 执行采集。Stop、SessionEnd 在进入脚本时复制一次记录，再以 `spawn(..., {detached:true, stdio:'ignore'})` 启动后台 worker 并 `unref()`；worker 忽略 SIGHUP，在约 0.1、1、5、60 秒采样，60 秒后用 `curl -I --max-time 15 https://example.com` 测联网。请求不携带会话内容。后台化仅用于本任务要求的 B/C 实验；控制命令均在前台等待返回。
- **记录路径只来自本轮自己的 hook 日志。** 没有列举或搜索 `~/.claude/projects/`、`~/.codex/`。原始记录副本只留在实验目录。提示只有合成口令、虚构纸风筝事实；实际工具调用仅为指定的 `printf`。强杀发生在已收到最后回复之后，只杀 `corral status` 返回的那一个 `agent_pid`，没有测试生成中途强杀。
- A2 按角色核对：用户消息中的 `SC_U_*` 与助手消息中的 `SC_A_*` 分别查验。不能用文件全文包含回答口令作为证据，因为用户提示也包含该口令。
- 旁路通过 stdin 收到 `jq` 抽出的用户/助手/工具文本，不接收整份原始记录。提取器不选系统、开发者、推理、配置或附件记录；本次用户文本另按合成 `SC_U_` 口令筛选。它是本轮样本提取器，不是完整会话格式适配器。
- 所有旁路设置独立的 `CAIRN_SC_CHILD=1`：实验 hook 仍记录事件，但不再派生 worker。这是实验防无限递归的限制，**不是 `CAIRN_DISABLE` 或 CLI 自动防递归的证明**。从旁路进程环境移除了继承的 `CORRAL_*` 和 `CLAUDECODE`，它们不是 Corral 管理的交互会话。

### A4. 格式与 jq 抽取

两家均为**通过、已查证**：本轮记录是一行一个 JSON 对象，`jq` 可逐行解析；不是只有自然语言对话。

| 对象 | Claude 本轮字段 | Codex 本轮字段 |
| --- | --- | --- |
| 用户提示 | 顶层 `type="user"`，`message.role="user"`；`message.content` 可以是字符串 | 顶层 `type="response_item"`，`payload.type="message"`、`payload.role="user"`，`payload.content[].type="input_text"`、`.text` |
| 助手文字 | `type="assistant"`，`message.role="assistant"`，`message.content[].type="text"`、`.text` | `response_item` → `payload.type="message"`、`role="assistant"`，`content[].type="output_text"`、`.text`；最终回答有 `phase="final_answer"` |
| 工具调用 | 助手块 `type="tool_use"`，`name`、`input`、`id`；本例 `name="Bash"` | `response_item` → `payload.type="custom_tool_call"`，`name="exec"`、`input`、`call_id`；`input` 中包含指定 shell 调用 |
| 工具结果 | 用户消息块 `type="tool_result"`，`tool_use_id`、`content`、`is_error`；不能把所有 user 消息都当人类提示 | `payload.type="custom_tool_call_output"`，`call_id`、`output` |
| 其他记录 | `attachment`、模式、标题、文件历史等 | `session_meta`、`turn_context`、`world_state`、`event_msg`、`token_usage_record` 等；event 里也可能重复描述消息/工具 |

实验提取命令：`jq -r -f bin/extract.jq <仅由本轮 hook 路径得到的副本>`。它按上述角色/类型输出 `user:`、`assistant:`、`tool_call:`、`tool_result:`，不同时提取 Codex 的 event 镜像以免重复。结果示例仅为合成值：

```text
user: Synthetic measurement SC_U_CE_01. ...
tool_call Bash: {"command":"printf SC_TOOL_CE_01",...}
tool_result: SC_TOOL_CE_01
assistant: SC_A_CE_01
```

证据：`bin/extract.jq`、`results/claude-exit-summary.input.txt`（318 字节）和 `codex-exit-summary.input.txt`（4,056 字节）。十回合源副本有 133 行、十个用户提示、十个最终回答、四条 `custom_tool_call` 及对应结果。完整结构的跨版本稳定性、分支/恢复/压缩/图片/多模态/子 agent 的通用抽取均未知；[Codex hooks 官方说明](https://learn.chatgpt.com/docs/hooks)也没有把 transcript 内部格式承诺成稳定 API。

## 3. B：hook 后台进程

### B1. 返回与退出后的存活

| 来源 / 退出方式 | 结果 | Stop 启动的 worker | SessionEnd 启动的 worker |
| --- | --- | --- | --- |
| Claude `/exit` | 通过 | 退出后仍完成 60 秒标记 | 同样完成，之后 Codex 摘要成功 |
| Claude `corral stop` | 通过 | 完成 | 完成 |
| Claude 强杀 | 部分通过 | 完成 | 没有该事件，未能启动 |
| Codex `/exit` | 通过 | 以第十回合 Stop 为证，退出后完成 | 完成，之后 Codex 摘要成功；C4 补充样本的 Claude 摘要也成功 |
| Codex `corral stop` | 部分通过 | 完成 | 本样本没有事件，未能启动 |
| Codex 强杀 | 部分通过 | 完成 | 没有该事件，未能启动 |

**已查证。** 对应目录都有 `after-60s.json`、`done.json`；worker 启动记录的 `ppid=1`，表明 hook 父进程已退出。worker 的 60 秒标记晚于对应退出/清理完成（十回合中早期 Stop 的 worker 有些在会话退出前已自然完成，不用那些样本证明“退出后存活”）。本轮一共 20 个 worker，最后逐 PID 检查均已退出。

探针 `received_ms → return_ms` 的业务段为 1–2 ms，旁路 hook 仅记录事件时为 0–1 ms；此计时**不包含 shell/Node 启动，不能当作完整 handler 的墙钟耗时**。实际事件均完成并有返回记录，未观察到 hook 超时。探针没有设置更长 timeout；但交互样本通过 Corral 注入其他 hooks，不能把它当成完全无其他 handler 的默认预算压力测试。

官方预算仍是 Claude SessionEnd 共享默认 1.5 秒（较长 handler timeout 可抬高）、Codex 默认 1 秒且最多 3 秒。模型调用是在 hook 父进程结束后才发生，不在这个同步业务段里。[Claude timeout](https://code.claude.com/docs/en/hooks#common-fields)、[Codex hook timeout](https://learn.chatgpt.com/docs/hooks)

没有测试普通 `command &`、只加 `nohup`、关闭整台机器、杀进程组、休眠、系统回收或长时间后台存活。结论只适用于本轮显式 detached、断开标准输入输出、忽略 SIGHUP 的方式；不能推出任意后台写法都存活。

### C3. Codex 是否可不留额外会话

**部分通过。** 本机 `codex exec --help` 与[官方非交互文档](https://learn.chatgpt.com/docs/non-interactive-mode#basic-usage)都有 `--ephemeral`，用途是不持久化 session rollout 文件。四次 Codex 旁路均使用此参数并成功输出摘要；有项目 hook 的三个调用中，四种事件都明确记录 **`transcript_path:null`**。

## 6. 对旁路摘要这条路的影响

只列实测限制与未测边界，不提出 cairn 的实现方案。

1. **已查证：Stop 不等于记录已含最后回答。** Claude 三个样本都有延迟，首个 122–124 ms 复查才看见；更慢的刷盘、长记录、磁盘异常未测。
2. **已查证：不能依赖所有退出方式都有 SessionEnd。** 两家强杀、Codex 本次 `corral stop` 均未观察到；最后已经完成的回合仍在，但生成中断、断电、崩溃和更早强杀未测。
3. **已查证：显式 detached 后台可以越过本轮会话退出继续执行。** 此结论不适用于任意 shell 后台方式；没有 SessionEnd 就没有该事件启动的 worker。系统回收、进程组终止和长时任务未测。
4. **已查证：旁路会形成新的 hook 事件。** `CAIRN_DISABLE=1`、`--ephemeral`、`--no-session-persistence` 都没使实验 hook 自动停止。无穷递归被实验标记拦住，未放任运行。
5. **已查证：不留会话参数下路径可能无效。** Codex 是 `null`，Claude 给的路径在结束后不存在；因此不能把每次 hook 的路径都当成可读文件。其他持久化痕迹未知。
6. **已查证：cwd 会改变本轮项目 hook 的触发结果。** 对其他用户级、插件、托管配置，以及未持久信任的项目组合，本轮没有作完整覆盖。
7. **已查证：摘要耗时明显长于同步 SessionEnd 默认预算，CLI 上下文也计入用量。** 两份 Codex 摘要约 28–30 秒，唯一一次 Claude 摘要约 9 秒；它们不代表延迟上限或模型比较。
8. **未知：通用抽取与内容质量。** 本轮只测简单文本和 shell 工具，未覆盖恢复/分支、压缩、媒体、子 agent、大上下文、模型失败、额度耗尽、授权失效或摘要遗漏/幻觉率。
