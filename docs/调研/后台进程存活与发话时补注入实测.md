# 后台进程存活与发话时补注入实测

2026-10-15，本机 macOS；Claude Code **2.1.300**，Codex **0.162.1**，Corral **0.1.0**，Rust **1.96.0**。仅回答 P1-06 的两个实测问题，不改设计、不出方案。

**结论：Claude 的正常退出和 `corral stop`、Codex 的 `corral stop` 样本中，Stop 起的 Rust 子进程均跑满自身的 5 分钟；两家第二次发话时的 JSON 补注入均被原样复述。Codex 正常退出未测成，不能据本轮判定该路径。**

## 方法与证据

沿用 `p1-lab/claude-repo/`、`codex-repo/`。项目 hook 配置先在原文件旁备份，临时只接 Stop、UserPromptSubmit，测完逐字恢复。保留 HOME 使用已有登录态，设置 `CAIRN_DISABLE=1` 和隔离的 `bgprobe/state/`；Claude 指定 `--model sonnet --effort medium`，Codex 指定 `-m gpt-5.6-luna -c 'model_reasoning_effort="medium"'`，未传扩大权限或沙箱的参数。这是本机既有默认配置下的结果，不代表干净安装的默认配置。

Rust 独立探针在 `p1-lab/bgprobe/` 编译。Stop 用 `Command::spawn`，子进程在 `pre_exec` 中调用 `setsid()`，三个标准流均接 `/dev/null`，父进程不等待；没有另加忽略 SIGHUP 的代码。worker 在 0、20、…、300 秒写 PID、PPID、SID、PGID、Unix 毫秒时间和单调计时，末行 `done` 后退出。每个成功对话样本两次 Stop，共 8 个 worker。

第一句只让模型心算 `2+3`，不调用工具或读文件。第一次 UserPromptSubmit 输出 `{}`；第二次才输出 `hookSpecificOutput.additionalContext`（附 `hookEventName: UserPromptSubmit`），携带各样本独有的合成口令。第二句只问有没有 hook 口令并要求原样复述，用户提示不含口令。hook 输入直接丢弃，不解析、不保存；没有读取任何会话记录、工具记忆、真实数据库或 Corral 事件文件，也没有调用旁路模型。除任务要求的脱离子进程外，控制和编译命令均在前台等到结束。

证据均留在仓库外 `/Users/firegnu/Developer/personal_projs/cairn-worktrees/p1-lab/bgprobe/`，不提交：

- `logs/<样本>/hooks.jsonl`：调用与返回前计时、worker PID、实际输出的 JSON；`worker-<hook PID>.jsonl`：存活与结束记录。
- `results/<样本>-*.json`：带命令起止时间的 start、wait、reply、send、exit/stop、status、按已知 PID 的 `ps` 回执；`analysis.json` 汇总逐 worker 结果。
- `results/restored.json`：版本、原配置与恢复配置的 SHA-256、一致性、收尾会话清单；`results/final-cleanup.json`：最终进程与测试会话核对。

## 结果

下表“退出后”均是从 `ps` 首次确认被测 agent PID 已消失，到 worker 的最后一行，故为**保守下界**；两列数字按第一轮、第二轮 Stop 排列。退出瞬间没有被精确采样。worker 的 5 分钟从自身启动算起，不是退出后再计满 5 分钟。

| 样本 / 实际关法 | Stop 探针返回前计时（ms） | 退出后继续写日志至少（秒） | 第二轮回复 | 判定与直接依据 |
| --- | --- | --- | --- | --- |
| `claude-exit` / `/exit` | 1.159 / 0.992 | 246.588 / 259.940 | `BG_claude_exit_7Q9M` | **已查证**：send 最终报 not_found；清理 stop 之前 status 已 not_found，PID 32057 已消失；两个 worker 跑满 300 秒 |
| `claude-stop` / `corral stop` | 0.950 / 1.168 | 292.555 / 298.285 | `BG_claude_stop_7Q9M` | **已查证**：stop 报 SIGHUP、退出码 129；PID 41239 消失；两个 worker 跑满 300 秒 |
| `codex-stop` / `corral stop` | 0.914 / 1.137 | 270.566 / 273.578 | `BG_codex_stop_7Q9M` | **已查证**：stop 报 keys、退出码 0；PID 58400 消失；两个 worker 跑满 300 秒 |
| `codex-exit-retry` / `/exit` 未退出，随后 stop 清理 | 0.874 / 1.233 | 清理后 261.387 / 265.459 | `BG_codex_exit_retry_7Q9M` | **已查证**：注入成功，清理后的两个 worker 跑满 300 秒；**未知**：正常退出后的存活，本样本不能证明 |

计时是 Rust `main` 入口到 stdout 刷新后、最后一条计时日志写入前的同步段，8 次为 **0.874–1.233 ms**。不含 OS 启动、最后日志写入及退出收尾，也不含宿主其他 hook 或调度耗时；**完整 handler 墙钟耗时未知**。已查证父 hook 没有等 worker 的 5 分钟，两轮回复和关会话都发生在 worker 完成前。

**已查证的进程关系**：8 个 worker 各有 16 行，覆盖约 300 秒，所有采样都是 `SID = PGID = PID`，`PPID = 1`，最后逐 PID 检查均已消失。启动记录关联了 hook PID 与 worker PID；第一次 worker 采样时已被 PID 1 接管，之后（包括关会话前后）PPID 没再变化。原 hook 父进程到 PID 1 的切换时刻没有被直接采到，不声称它是在关会话时才发生。

### Codex 没测成的部分与会话数

实际创建 **5 个**测试会话，无第六个：`cairn/test-bg-claude-exit-1`、`cairn/test-bg-claude-stop-1`、`cairn/test-bg-codex-exit-1`、`cairn/test-bg-codex-exit-retry-1`、`cairn/test-bg-codex-stop-1`。全部已退出，最终 `corral ls` 无本轮测试会话。

- **已查证**：首个 Codex 会话 start 返回成功，但首次 wait 报退出码 2，未得到回复、未留下本探针日志。记录是 `results/codex-exit-start.json`、`codex-exit-wait1-1.json`、`codex-exit-failed-{reply,cleanup}.json`。
- **推测，未确证**：显式重复传 `--dangerously-bypass-hook-trust` 可能导致启动失败（Corral 也注入该参数）。去掉重复参数后，允许的一次重做成功进入两轮对话；未拿到原会话的错误正文，不能据重做成功认定根因。
- **已查证 / 正常退出未知**：重做样本 `send /exit` 报 `not_delivered`；紧接着 status 仍 idle、PID 49565 仍存在。未重发、未用 keys 补回车，直接 `corral stop` 清理，回执 keys、退出码 0。证据为 `codex-exit-retry-{exit,status-after,process-after,cleanup,process-cleaned}.json`。因此本轮没有有效的 Codex 正常退出样本；不把“不退出”解释成后台进程能力失败。

## 信任、遗留物与边界

没有弹出需要用户点的信任框，没有代点或授予持久信任。沿用既有目录信任；Codex 运行使用 Corral 的当次 hook 信任豁免，首次失败启动还显式重复传过该参数。当次豁免随进程退出失效，**本轮未主动新增 Codex 持久 hook 信任记录**；没有读取真实信任存储，CLI 是否自行写入其他元数据未知。既有持久 hook 信任由用户在 Codex `/hooks` 中撤销；项目目录信任清除位置沿用 P1-04 的记录：Codex `~/.codex/config.toml` 对应项目的 `trust_level`，Claude `~/.claude.json` 对应项目的 `hasTrustDialogAccepted`，本轮未重新核查或修改这些条目。
