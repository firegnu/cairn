## 方法与边界

沿用 P1-04 的两个合成仓库、项目 hook 配置位置和 `extract.jq`。每家仅发送一个合成回合，要求按顺序读 16 个小文件，每步单独调用工具，读后报告该步口令。文件内容中的 `SC_TOOL_*` 不写进用户提示；按助手角色和匹配的工具 ID 核对，不能靠全文命中口令判断完成。

前台监视器每约 100 ms 查看自己的 hook 日志和记录；观察到第三次 PostToolUse，且记录里至少已有两个工具结果后，重新用 `corral status` 确认本会话 `state="working"`、尚无 Stop，只对其中的 `agent_pid` 发 SIGKILL，随后立即 `corral stop`。不延迟 hook、不挂后台 worker、不调用旁路模型。记录路径只取自本轮自己的 hook 日志，没有列举工具状态目录；原始材料留在仓库外。

Claude 参数为 `--model sonnet --effort medium`；Codex 为 `-m gpt-5.6-luna -c 'model_reasoning_effort="medium"'`。均带 `role=test`、`CAIRN_DISABLE=1` 和独立的 `XDG_STATE_HOME`，保留 HOME 使用现有登录态，不另加权限或沙箱扩大参数。hook 只保存事件、时间、路径、关联及工具名等字段，不保存输入的 `prompt`、`last_assistant_message`、工具输入或输出，不注入内容、不续跑。

## 杀入时点、事实边界与启动次数

- **已查证**：Claude 于 `06:49:10.909Z`、Codex 于 `06:53:52.399Z` 被杀，分别晚于第三次 PostToolUse 探针收到输入 **100 ms / 85 ms**。两者前三次读取已经完成，16 步回合尚未结束；没有把回合结束后的强杀当作本题证据。
- **已查证的有限观察**：最终复查距强杀分别约 **338 秒 / 56 秒**，两家均没有 Stop、SessionEnd。最终记录与 stop 清理后第一份副本的 SHA-256 一致。证据为 `results/analysis.json`、`<工具>-kill.json`、`<工具>-status-before-kill.json`、`<工具>-stop.json` 和 `events/`。
- **未知**：第三步读后助手文字是尚未生成还是未落盘，不能仅凭缺失区分；更早的杀入点、生成中的半条内容、其他版本或负载下会留下多少，未测。不由这两个样本推断一般可靠性，也不将未观察到事件表述为所有强杀永不触发。
- **实际调用 `corral start` 三次**：`cairn/test-mt-claude-1`、`cairn/test-mt-codex-1`、`cairn/test-mt-codex-retry-1`。Claude 一次成功；Codex 第一次启动后自行退出、无本轮 hook 日志，唯一一次重做成功。有效合成回合各一个，没有额外模型调用。
- **第一次 Codex 失败的推测**：显式添加的 `--dangerously-bypass-hook-trust` 与 Corral 自带注入重复。已查证本机 CLI 对两个该参数报 `cannot be used multiple times`、退出 2（仅 `--help` 参数解析检查，没有启动测试会话）；但首个进程的退出错误未取到，不能把推测当作已捕获的根因。重做只去掉显式重复参数，由 Corral 注入当次 hook 信任豁免；不扩大工具权限。证据在 `results/codex-first-attempt/`、`codex-duplicate-option-check.json`、`codex-start-args.json`。
