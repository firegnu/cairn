# 注入加到 9,000 字符实测

2026-10-15，本机 macOS；Claude Code **2.1.300**（指定 `sonnet / medium`，界面显示 Sonnet 5.5），Codex **0.162.1**（`gpt-5.6-luna / medium`），Corral **0.1.0**。

**本轮没有证明两家都能逐字符完整收到。Codex limit 6000 的回显缺失中段；9000 的 60 个口令全部正确，但正文仍漏 6 字符。Claude 因回显请求被拦截，完整性未知。**

## 方法

沿用 `p1-lab/claude-repo/`、`codex-repo/`，两份项目 hook 配置先在旁边备份，临时只配置本实验的 SessionStart handler。Node 辅助脚本生成同一份 **60 行、每行 150 字符（含换行）、共 9,000 Unicode 字符 / 24,600 UTF-8 字节**的中文合成样例；每行有独立随机的 16 位十六进制口令，覆盖开头、中段、结尾。正文为四种虚构场景的随机排列，定长切齐，行尾可能是半句。

hook 丢弃 stdin，不解析或保存输入，输出 JSON `hookSpecificOutput.additionalContext`，附 `hookEventName: SessionStart`。三个会话各留下一次 hook 输出日志，均为同一份 9,000 字符。先用启动提示要求只回 `READY`，再通过 `corral send` 要求回显合成正文；提示不含口令，禁止工具调用、文件读取（包括溢出文件）和保存记忆。用 `corral reply` 取回复，逐字符及逐口令比较；公开 wait 状态的 `last_tool` 均为 null，没有读取会话记录来审计工具调用。

全部会话带 `CAIRN_DISABLE=1` 和隔离的 `budget/state/`，保留 HOME 使用既有登录态；未指定扩大权限、沙箱的参数。这是本机既有默认配置下的结果，不代表干净安装环境。所有命令前台等待完成。

**推测**：6000 的中间缺口符合预算截断表现；9000 的零散漏字可能是转写错误。没有读取宿主内部上下文，二者不能直接确认为原因。9000 那轮还在提示中说明“定长行尾半句不表示缺失”，以免模型给每行添 MISSING；这也是两轮提示的差异。**未知**：9000 是否逐字符完整注入、最小够用值及其他文本的表现。本轮只能给出 **9000 通过全部口令检查**，没有找到经全文严格比较通过的值。

实际创建 **3 个**测试会话：`cairn/test-budget-claude-1`、`cairn/test-budget-codex-6000-1`、`cairn/test-budget-codex-9000-1`。Claude 的一次重试复用原会话，没有再开会话；没有其他重试。取完回复立即 `corral stop`，最终 `results/final-agents.json` 中无本轮测试会话。Claude 末次回复为拒绝；首次失败后 reply 仍是旧 READY，未将其计作回显结果。
